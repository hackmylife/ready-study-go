# Why?

`Reverse`がbyte単位で反転すると、`"Go言語"`は正しいUTF-8でなくなります。二回反転すると元に戻るため、往復の性質だけではこの欠陥を検出できず、`ValidString`の性質が必要です。逆に何もしない`Reverse`はUTF-8も往復も満たすので、`"Go言語"`の先頭`'G'`と結果の先頭`'G'`が一致する(末尾の`'語'`と一致しない)ことで検出します。性質は一つずつでは弱く、組み合わせて欠陥を囲みます。

# Alternatives

`[]rune`へ変換して`slices.Reverse`で反転した結果と比べる方法もあります。ただし検証対象と同じ手順をテストに書くと、同じ誤りをテストも持ちます。性質による検証は実装手順に依存しません。

# Idiomatic Go

`go test`は通常の実行でseedと`testdata/fuzz`の入力だけを使い、`-fuzz`を付けたときだけ新しい入力を生成します。探索で見つかった入力はファイルとして残り、回帰テストになります。

# 振り返り

`t.Skip`を外して`go test -fuzz=FuzzReverse`を実行し、どんな入力で失敗するか確認してください。その入力を`Reverse`へ渡すと何が起きるか説明しましょう。
